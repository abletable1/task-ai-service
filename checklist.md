# Чек-лист ручных проверок

Подготовьте `.env` и сертификаты по README, запустите сервер.
Запросы можно выполнять через Swagger UI, curl или Postman.
Фиксируйте HTTP-статус, JSON-ответ и события в `logs/service.jsonl`.

## API и валидация

- [ ] `GET /health`: HTTP 200 и `{"status":"ok"}`.
- [ ] `/docs/` открывается; `/health` и `/chat` вызываются через Try it out → Execute.
- [ ] Корректный `/chat`: HTTP 200, непустое резюме соответствует исходному тексту, `cached: false`.
- [ ] Отсутствующий message: HTTP 400 с понятным сообщением.
- [ ] Пустая строка, пробелы или число в message: HTTP 400.
- [ ] 1000 символов допускаются; 1001 символ возвращает HTTP 400.
- [ ] Невалидный JSON или неверный Content-Type: HTTP 400.
- [ ] Тело больше 16 КБ: HTTP 413.

## Кеш и устойчивость

- [ ] Точный повтор: HTTP 200, тот же ответ, `cached: true`, событие `cache_hit`; генерация не повторяется.
- [ ] С TTL 2 секунды: немедленный повтор из кеша, повтор через 3 секунды — новая генерация. После проверки вернуть TTL 600.
- [ ] При отключённой сети незакешированный запрос даёт HTTP 503 с fallback после ограниченных попыток.
- [ ] Закешированный запрос при отключённой сети возвращает HTTP 200 и `cached: true`.
- [ ] После восстановления сети запрос, ранее давший fallback, выполняется заново: ошибки не кешируются.
- [ ] `python -m tools.demo` подтверждает HTTP 502 для невалидного JSON провайдера и HTTP 503 при закрытии его порта.

## Авторизация и наблюдаемость

- [ ] OAuth-токен переиспользуется между разными запросами: событие `oauth_token_hit`.
- [ ] Корректный CA bundle настроен, проверка HTTPS-сертификатов включена.
- [ ] Консоль и файл содержат JSON-логи с request_id, промптами, ответами, ошибками и временем этапов.
- [ ] Ключ авторизации и access token отсутствуют в логах.

## Артефакты

- [ ] Сохранены скриншоты или видео: успешный запрос, ошибка ввода, fallback, ответ из кеша.
- [ ] Установка и запуск выполняются по README из чистого клона репозитория.
- [ ] В публикуемых файлах отсутствуют ключи, локальные настройки и логи.
