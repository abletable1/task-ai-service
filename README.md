# Сервис суммаризации на GigaChat

Учебный HTTP-сервис на Python и Flask. Принимает текст, формирует запрос
к GigaChat и возвращает краткое резюме на русском языке. Для вызова API
из браузера доступен Swagger UI.

## Возможности

- Валидация JSON и текста: непустая строка, максимум 1000 символов.
- Системная инструкция и отдельный пользовательский промпт.
- OAuth-авторизация с переиспользованием и обновлением access token.
- Таймауты, ограниченные ретраи и fallback при недоступности провайдера.
- Кеш результатов с TTL и ограничением количества записей.
- Структурированные JSON-логи с длительностью этапов и идентификатором запроса.
- Автоматические тесты и демонстрация с локальным провайдером-заглушкой.

## Установка

Требуются Python 3.9+ и ключ авторизации GigaChat. Команды выполняются
из корня клонированного репозитория.

Windows / PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m tools.setup_certificates
```

Linux / macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m tools.setup_certificates
```

При повторной установке сохраняйте существующий `.env`.
Для воспроизведения проверенного набора зависимостей на Python 3.12
можно установить `requirements.lock.txt` вместо `requirements.txt`.

## Настройка

Заполните `.env`:

```dotenv
GIGACHAT_AUTH_KEY=ваш_ключ_авторизации
GIGACHAT_MODEL=GigaChat-2
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_CA_BUNDLE_FILE=certs/ca-bundle.pem
```

`GIGACHAT_AUTH_KEY` — готовое значение **Authorization key** из кабинета
GigaChat. Вставляйте его без префикса `Basic` и повторного Base64-кодирования.
Сервис самостоятельно получает временный access token.

Scope должен соответствовать доступу аккаунта:

| Scope | Тип доступа |
| --- | --- |
| `GIGACHAT_API_PERS` | Физические лица |
| `GIGACHAT_API_B2B` | ИП и юридические лица, предоплаченные пакеты |
| `GIGACHAT_API_CORP` | ИП и юридические лица, pay-as-you-go |

Модель задаётся в `GIGACHAT_MODEL`; её доступность зависит от аккаунта.
Список настроек с исходными значениями находится в [.env.example](.env.example).
Переменные окружения имеют приоритет над `.env`. Изменения применяются
после перезапуска сервера.

## Запуск

Windows:

```powershell
.\.venv\Scripts\python.exe main.py
```

Linux / macOS:

```bash
.venv/bin/python main.py
```

После активации виртуального окружения достаточно `python main.py`.
Для остановки нажмите **Ctrl+C**.

Swagger UI: **http://127.0.0.1:8000/docs/**.
Раскройте endpoint, нажмите **Try it out**, заполните запрос и нажмите
**Execute**. Ключ авторизации задаётся на сервере; вводить его в Swagger не нужно.
JS/CSS интерфейса загружаются локально.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/chat` | Суммаризация текста |
| `GET` | `/health` | Проверка работы сервера |
| `GET` | `/docs/` | Swagger UI |
| `GET` | `/openapi.json` | Спецификация OpenAPI 3.0 |

`/health` проверяет сервер без обращения к GigaChat.

Запрос `POST /chat`, `Content-Type: application/json`:

```json
{"message":"Команда разработала сервис. Он суммаризирует тексты и кеширует результаты."}
```

Пример успешного ответа, HTTP 200:

```json
{
  "answer": "Команда создала сервис суммаризации с кешированием результатов.",
  "cached": false,
  "scenario": "summarize",
  "model": "GigaChat-2",
  "request_id": "example-request-id"
}
```

Формулировка резюме зависит от модели. Точный повтор в течение TTL
возвращает сохранённый ответ с `cached: true`.

Пример вызова в PowerShell:

```powershell
$body = @{message = 'Команда разработала сервис суммаризации с кешем.'} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/chat -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

Пример вызова curl / bash:

```bash
curl -i http://127.0.0.1:8000/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"Команда разработала сервис суммаризации с кешем."}'
```

Ошибки:

| HTTP | Причина |
| --- | --- |
| `400` | Отсутствующий, пустой или слишком длинный message; неверный JSON или Content-Type |
| `413` | Тело запроса больше 16 КБ |
| `502` | Невалидный JSON провайдера, пустой или незавершённый ответ модели |
| `503` | Недоступность провайдера, ошибка авторизации или отсутствие ключа |
| `500` | Внутренняя ошибка сервиса |

Пример ошибки ввода:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Поле message обязательно и должно быть непустой строкой."
  },
  "request_id": "example-request-id"
}
```

Пример fallback:

```json
{
  "answer": "Сервис временно недоступен, попробуйте позже.",
  "cached": false,
  "error": {
    "code": "llm_unavailable",
    "message": "Сервис временно недоступен, попробуйте позже."
  },
  "request_id": "example-request-id"
}
```

## Архитектура

```text
HTTP → валидация → бизнес-логика → prompt builder → кеш
     → OAuth → GigaChat → постобработка → кеш → JSON-ответ
```

| Каталог / файл | Назначение |
| --- | --- |
| `api/` | HTTP-эндпоинты и Swagger |
| `services/` | Бизнес-логика и логирование |
| `llm/` | HTTP-клиент, промпты и постобработка |
| `cache/` | Потокобезопасный кеш с TTL |
| `config/` | Настройки, подготовка окружения и OpenAPI |
| `tests/` | Автоматические проверки |
| `tools/` | Подготовка сертификатов и локальная демонстрация |
| `main.py` | Точка входа |

Промпт содержит сообщения `system` и `user`. Постобработка проверяет
`finish_reason: stop`, роль `assistant` и непустой текст, затем очищает
лишние пробелы. Незавершённые ответы и ограничения модели возвращаются как 502.

## Устойчивость и кеш

Каждый OAuth/LLM-вызов имеет сетевой таймаут 15 секунд и максимум 3 попытки
с задержками 1 и 2 секунды. Повторяются ошибки соединения, таймауты и
HTTP 408/429/5xx. Постоянные HTTP-ошибки, ошибки парсинга и TLS не повторяются.
При 401 генерации токен обновляется один раз в пределах лимита попыток.
Токен хранится в памяти и обновляется за 30 секунд до истечения срока.

Кеш хранится в памяти процесса: TTL 600 секунд, максимум 1000 записей.
Ключ учитывает текст, системный промпт, модель, температуру, лимит ответа,
адрес API и scope. Ошибки и fallback не кешируются.

Кеш очищается при перезапуске и не разделяется между процессами.
Одновременные одинаковые запросы могут вызвать модель несколько раз.
Таймаут ограничивает сетевые операции, а не полное время обработки запроса.
Встроенный сервер Flask предназначен для локального запуска.

## Сертификаты и логи

`python -m tools.setup_certificates` создаёт `certs/ca-bundle.pem`, объединяя
стандартные корни certifi с корневым сертификатом Минцифры из официального
источника Госуслуг. Системное хранилище сертификатов не изменяется.
Можно задать собственный PEM bundle в `GIGACHAT_CA_BUNDLE_FILE`;
относительный путь считается от корня проекта. Проверка TLS включена.

JSON-логи выводятся в консоль и `logs/service.jsonl`. Файл ротируется
при 2 МБ, сохраняются три резервные копии. События содержат `request_id`,
cache hit/miss, промпты, ответы, ошибки и длительность выполненных этапов.
Идентификатор также возвращается в заголовке `X-Request-ID`.

Ключ авторизации, access token и OAuth-ответы не логируются.
Пользовательский текст и ответы модели записываются в лог.
При диагностике `operation: oauth` означает получение токена,
`operation: llm` — генерацию. `causes` содержит типы вложенных сетевых
ошибок и их числовые коды.

Если `SSLKEYLOGFILE` указывает на отсутствующую папку, сервис отключает
эту необязательную настройку TLS-отладки только внутри своего процесса.
При аналогичной ошибке во время создания окружения или установки зависимостей
её можно сбросить в PowerShell: `$env:SSLKEYLOGFILE = $null`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m tools.demo
```

В Linux / macOS используйте `.venv/bin/python`.
Автоматические тесты не требуют ключа или доступа к реальной модели.
Демонстрация запускает локальные HTTP-серверы приложения и заглушки GigaChat,
проверяет успешный запрос, кеш, валидацию, невалидный JSON и сетевой сбой,
затем останавливает серверы.

Сгенерированные результаты сохраняются в `artifacts/demo.json` и
`artifacts/demo.html`. Откройте HTML для просмотра и скриншотов.
Результаты демонстрации, логи, сертификаты и `.env` исключены из Git.
